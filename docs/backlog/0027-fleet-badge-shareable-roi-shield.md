## User story

As a fleet operator who has been running the loop on a project for 3+
weeks and wants to put proof in the project's own `README.md` that an
autonomous fleet is doing actual work — without exposing the events
channel or wiring a cloud badge service — I want
`bin/fleet badge <slug> [--since 30d] [--format md|svg|txt]` to emit
one line (markdown image, raw SVG, or plain text) summarizing the
project's last-N-day fleet output (e.g. `agent-fleet: 14 PRs, $5.83,
last ship 6h ago`) that I can paste into the project's README and
re-generate on a cron, so that the kit's earned-its-keep claim is
made VISIBLE on the project where the work landed instead of hidden
inside `events.jsonl`.

## Why now (four lenses)

### Product Owner
`fleet weekly` (0025) is a private artifact — the operator runs it in
their terminal on Sunday morning. The kit has no SHAREABLE artifact
today. Every other open-source tool with traction ships a badge
mechanism precisely because badges become the project's public proof:
build status, code coverage, npm version, license. For an autonomous
agent kit the natural proof is "this fleet has shipped N PRs for $X
in the last 30 days." Smallest unit of value: one command, one line of
output, one operator decision (paste-into-README or don't). The
operator gets ONE new daily question answered: "can I show someone
what the fleet did?" The answer becomes "yes — `fleet badge agent-fleet
--format md` and paste."

### Stakeholder
This is an acquisition compound. The kit's adoption story today
hinges on `fleet kickstart --demo` (0023) — a curious adopter sees
the loop run end-to-end in 60 seconds. But the demo is a synthetic
one-shot; it does not convey "this is what 30 days of running it
looks like." `fleet badge` closes that gap because every operator
who keeps the loop running for 30 days now has a one-line public
artifact they can paste anywhere. The badge is also the natural
linkable surface from a project's README back to agent-fleet itself
(the `--format md` output includes an anchor link to the kit repo) —
turning every adopting project into a discovery node. No cloud
service, no API key, no third-party shields.io dependency: every
byte the badge needs is already in the local events.jsonl, runs.jsonl,
and the manifest. This is the smallest-possible moat-deepening
artifact: pure-shell, additive, leverages every existing telemetry
contract.

### User (operator after a successful month, README half-edited in
front of them)
Runs `bin/fleet badge agent-fleet --since 30d --format md`. Sees:

```
[![fleet](https://img.shields.io/badge/agent--fleet-14_PRs%20%2F%20%245.83%20%2F%2030d-blue)](https://github.com/mutaaf/agent-fleet) <!-- generated by fleet badge -->
```

Pastes that single line at the top of the project's `README.md`,
commits, pushes. The badge renders. Anyone visiting the README sees
"14 PRs / $5.83 / 30d" inline with the build-status and coverage
badges. The operator gets a small surge of "this is real" — the
fleet's output is now a public, durable claim. Operator also pipes
`fleet badge agent-fleet --format svg > docs/fleet-badge.svg` for an
offline-renderable SVG (no shields.io round-trip required), which
the operator may prefer for a private fork.

### Growth
"Show, don't tell" matters for any kit competing for an operator's
attention. The badge is the kit's first SHAREABLE artifact (the demo
is shareable but ephemeral; the badge is durable). Every project that
adopts the badge becomes a passive discovery surface — anyone reading
that project's README is one click from the kit. This is the
single-highest-leverage acquisition surface the kit can ship without
adding a website or a marketing site, because it lives where the
operator already does work: the project's own README. Comparable to
how the GitHub Actions badge made CI universal once the badge was a
copy-paste line.

## Acceptance criteria

Each box maps 1:1 to a test scenario in `tests/badge.sh`.

- [ ] `bin/fleet badge <slug>` (no flags) defaults to `--since 30d`
      and `--format md`. Exits 0. Prints exactly one line of output
      (no trailing newline visible to a `tr -d '\n' | wc -c` check
      beyond the line itself). The line includes a shields.io image
      URL with the project's slug, PR count, dollar spend, and
      window-size labels URL-encoded (`%20` for space, `%24` for
      `$`, `%2F` for `/`). The test fixtures a synthetic runs.jsonl
      / events.jsonl and asserts the exact line via byte-exact
      comparison against a checked-in golden.
- [ ] `--since <Nh|Nd>` parses via `digest_parse_since` (line ~1133).
      Invalid values print `badge: invalid --since "<v>" (use Nh or
      Nd)` to stderr and exit 2. Window appears in the badge label
      (`30d`, `7d`, `48h`, etc.). Test covers `30d`, `7d`, `48h`,
      and an invalid `forever`.
- [ ] `--format md` (the default) emits a markdown image with link:
      `[![fleet](<shields-url>)](<repo-url>) <!-- generated by
      fleet badge -->`. The `<repo-url>` is the manifest's
      `REPO_URL` value (NOT the kit repo — the kit repo is linked
      via the alt-text only). The trailing HTML comment is a
      deterministic regenerate marker: a future ticket / a cron
      can sed-replace any line matching `<!-- generated by fleet
      badge -->` and the badge updates without manual edits.
- [ ] `--format svg` emits a self-contained raw SVG (no external
      URL fetch — the SVG is generated locally using a fixed
      shields.io-style template with width computed from the
      label text length). The SVG body starts with `<?xml version`
      and ends with `</svg>`. Test pipes the output through `head
      -1` to assert the XML prelude and `tail -1` to assert the
      closing tag. NO network call is made — the test runs with
      `gh` and `curl` stubbed to fail and the command MUST still
      succeed.
- [ ] `--format txt` emits a plain string suitable for piping into
      an ntfy/email body: `<slug>: <prs> PRs, $<spend>, <since>
      (last ship <Nh|Nd> ago)`. The "last ship" age is the mtime
      of the newest log file under the project's cache (reuses
      `newest_log_epoch()` line ~69 + `human_age()` line ~55).
      Test asserts the exact string.
- [ ] PR-count metric: counts merged agent PRs in the window via
      the SAME runs.jsonl heuristic `fleet weekly` uses (ticket
      0025 AC#2 — `result_head` starting with `SHIP `). Reuses
      `weekly_ship_count_since()` (line ~1538). No `gh api` call
      — the badge must work offline. Test seeds a runs.jsonl
      with three ship rows in window and asserts `3 PRs` (singular
      form `1 PR` when count is 1; the test covers both).
- [ ] Spend metric: `digest_spend_since` (line ~1164) reused.
      Rendered as `$N.NN`. Zero spend renders as `$0.00`. Test
      asserts both branches.
- [ ] When the project has zero events AND zero runs in the window,
      the badge still renders with `0 PRs, $0.00`. The HTML
      comment marker is still present. This is intentional: an
      operator who pastes the badge before the fleet has shipped
      anything should see "0 PRs" honestly, not a missing badge.
      Test asserts the cold-project line.
- [ ] Unknown slug: `badge: no project with SLUG=<slug> found
      (looked under FLEET_DISCOVERY_ROOT=<path>)` to stderr,
      exit 2. Test asserts the exact error and exit code.
- [ ] Help: `bin/fleet badge --help` prints a USAGE block listing
      every flag (`--since`, `--format`, `--repo`, `--help`) plus
      a one-line example for each format. The `validate` job's
      shellcheck pass is the relevant gate (no extra check). Test
      asserts the help banner mentions `--since`, `--format`,
      `--help` via `grep -qF -- "$kw"` (per LESSONS 2026-05-30 —
      `grep -F --` to defend against flags as patterns).
- [ ] `--repo <URL>` override: when present, the linked target in
      the markdown badge is the override URL instead of the
      manifest's `REPO_URL`. This is the one knob for operators
      whose project's GitHub canonical URL differs from the manifest
      (forks, vanity URLs). Test asserts the override path renders
      a different anchor.
- [ ] No new event types. `badge` is a pure consumer of the
      existing telemetry channel (P-6: telemetry is the source of
      truth; readers compose, they do not invent). The PR body
      affirms "no new event types added; no AGENTS.md § Telemetry
      append needed."
- [ ] `tests/badge.sh` covers all twelve boxes using
      `$HOME/.local/bin` stubs (per LESSONS 2026-05-26) — no
      network call is permitted; the test sets `curl` and `gh`
      to fail-on-invoke stubs. `FLEET_DISCOVERY_ROOT` is redirected
      to `tests/fixtures/badge/`. Goldens live at
      `tests/fixtures/badge.md.golden.txt`,
      `tests/fixtures/badge.svg.golden.txt`,
      `tests/fixtures/badge.txt.golden.txt`. Run-time budget: <10s.

## Out of scope

The dev agent will NOT do these even if they seem related.

- Hosting the badge as a service. The kit is shell-only;
  introducing a server (or a shields.io endpoint of our own)
  violates the no-non-shell-deps Hard NO and changes the kit's
  shape entirely. The `--format svg` path produces a self-contained
  SVG precisely so no service is needed.
- Auto-updating the README of every fleet project. The operator
  pastes the line manually (or pipes it via their own cron). The
  kit does NOT touch the project's README — that would be a
  side-effect on the operator's source tree.
- Multi-project badges (`fleet badge --all`). Each badge is one
  project; aggregating across projects would conflate slugs and
  is the `fleet overview` (0019) / `fleet weekly` (0025) territory.
- A "badge JSON endpoint" (e.g. for shields.io's dynamic-badge
  endpoint). Adding a JSON contract here would couple the kit to
  shields.io's schema, which is theirs to change. The static URL
  with embedded label keeps us decoupled.
- Auto-regenerating the badge on a launchd job. Like `weekly` and
  `inbox`, the operator runs it by hand or pipes through their own
  cron. Adding a launchd surface adds an uninstall surface for zero
  added value.
- Color logic that turns the badge red when send-back rate is high.
  Color is a future ticket; v1 ships a fixed blue. Per P-1
  (smallest viable change), the color thresholds and signal
  selection deserve their own ticket so we don't bake an
  unconsidered policy into the public badge.
- Linking the badge to a per-project HTML report. There is no HTML
  report yet (and won't be in this ticket); the anchor goes to the
  manifest's `REPO_URL`.

## Engineering notes

Files / patterns the dev should touch. Specific enough that the dev
doesn't have to re-discover the architecture.

- `bin/fleet` — new `badge()` dispatcher next to `weekly()` (line
  ~1653) and the kickstart/onboard cluster. Shape mirrors
  `weekly()`: `--since` parsing via `digest_parse_since`,
  discovery via `discover()` (line ~44), slug lookup via the
  rollback/kickstart-style `*_resolve_manifest` pattern (line
  ~2678/~3022) — extract a `badge_resolve_manifest()` that wraps
  the same union.
- `bin/fleet` — `badge_url_encode()` is the one new helper —
  URL-encode space, `$`, `/`, `:`, `(`, `)` in the label segment.
  Pure shell, no `python3` dep (per the no-non-shell-deps rule;
  `lessons_sync` falls back to shell-only too — ticket 0009).
  Translation table: ` ` → `%20`, `$` → `%24`, `/` → `%2F`, `(` →
  `%28`, `)` → `%29`, `:` → `%3A`, `-` → `--` (shields.io
  convention).
- `bin/fleet` — `badge_render_md()`, `badge_render_svg()`,
  `badge_render_txt()` — one per `--format`. The SVG body is a
  static template string with two placeholders (label, value);
  width is computed as `len(label+value)*6 + 20` (the classic
  shields.io "flat" preset proportion). Hand-rolled, no external
  template engine.
- `bin/fleet` — help banner block at the top of the file gets a
  new line: `fleet badge <slug>           one-line ROI badge for
  the project's README (md/svg/txt)`. README "Daily ops" code
  block gets the same.
- `lib/common.sh` — NO changes. `badge` is a pure reader; per
  P-6 it does not emit new events. The PR body affirms this so
  the reviewer's telemetry-contract check stays satisfied. NO
  `fleet_*` signature changes — additive subcommand only.
- `prompts/` — NO changes. The command is operator-facing only;
  no agent prompt reads `fleet badge`. No `Reinstall: all
  projects` line is needed because `lib/` and `prompts/` are
  untouched.
- `tests/fixtures/badge/` — NEW directory under
  `tests/fixtures/` holding one synthetic `agents.config.sh`
  plus its `events.jsonl` and `runs.jsonl` content. Three goldens
  side by side (md, svg, txt). Per LESSONS 2026-05-27, the test
  uses `cp` for backup/restore around any host file it touches —
  never `$(cat …)`.
- `tests/badge.sh` — top of file mirrors `tests/weekly.sh`:
  redirect `FLEET_DISCOVERY_ROOT`, stub `gh` and `curl` under
  `$HOME/.local/bin` to fail-on-invoke (asserting the badge does
  not require network), `mktemp -d` for the fixture under
  `$HOME`. The SVG-format test parses the output via `xmllint
  --noout -` if `xmllint` is available; if not, falls back to
  a `head -1` / `tail -1` syntactic check (most macOS hosts have
  `xmllint`, Ubuntu CI has it via `libxml2-utils` — but the test
  must not REQUIRE it).
- New deps: none. Pure shell + awk + the existing JSONL parsing
  helpers (`digest_parse_since`, `digest_spend_since`,
  `weekly_ship_count_since`, `human_age`, `newest_log_epoch`).
- Public API: additive — `bin/fleet badge` is a new subcommand,
  no new event types, no `fleet_*` signature changes.
- BREAKING flag: NO. PR body affirms "no `fleet_*` signature
  changes" and "no new event types added."
- Reinstall required: NO. `lib/` and `prompts/` are untouched.
- LESSONS to defend against: 2026-05-26 (`tail` shadowed
  `/usr/bin/tail` — `badge` does not collide with any common
  binary on macOS or Linux, confirmed via `command -v badge`
  returning nothing). LESSONS 2026-05-28 (`printf '-…'` trap)
  applies because the `--repo` URL value can start with `-` if
  malformed — use `printf -- '%s' "$repo"` defensively. LESSONS
  2026-05-30 (`grep -F --`) applies to the help-text assertion
  in the test.
- This ticket compounds 0002 (events.jsonl), 0004 (spend), 0012
  (digest_parse_since), 0025 (weekly_ship_count_since). It
  introduces ZERO new substrate; every primitive it reads already
  exists. Per P-1 the diff is small: ~200 lines of `badge*`
  helpers + a 30-line SVG template + ~100 lines of test fixture
  content + one help-text line.
