## User story

As a fleet operator who already runs `fleet morning` (0036), `fleet weekly`
(0025), `fleet badge` (0027), and `fleet streak` (0042) — but who, when a
friend on Hacker News / a coworker on Slack / a recruiter on a portfolio
review asks "what does this autonomous-agent thing actually DO for you?",
has NO single command whose output I can SCREENSHOT and PASTE into a
public conversation — I want `bin/fleet recap [--since 30d] [--public]`
to print a 12-to-18-line, terminal-rendered, narrative snapshot of the
last N days across the whole fleet (PRs merged, $ spent, streak active,
top lesson promoted, top heal pattern, kit SHA, prompts pin), with a
public mode that strips slug names down to `project-1 / project-2 / ...`
and never mentions a private PR number, so I can post it WITHOUT
hand-editing what the kit shows me.

## Why now (four lenses)

### Product Owner
Every existing telemetry surface is OPERATOR-PRIVATE by design — they
show real slug names, real ticket ids, real PR numbers, real dollar
amounts tied to identifiable projects. That's the right shape for the
operator's 9am check-in. It is the WRONG shape for a public post.

When a friend asks "what does agent-fleet actually do?" today, the
operator's options are:

- (a) Paste a screenshot of `fleet weekly` and hand-redact slug names
  in a follow-up message ("ignore the `courtiq-staging` line, that's
  internal").
- (b) Paste a screenshot of `fleet badge` (a single shields.io-style
  line — too thin to convince a skeptical reader).
- (c) Write a paragraph from scratch.

(a) is friction the operator does not pay (and ends up posting
nothing). (b) is too small to carry the story. (c) is what the
operator should not have to write — the loop should compose it.

The smallest meaningful unit of value is one command, one
screenshot-shaped block:

```
fleet recap --since 30d --public

agent-fleet · 30-day recap · 2026-05-14 → 2026-06-13

5 projects, 47 PRs merged by autonomous agents, $6.18 total spend
median cost per shipped ticket: $0.41 · longest active streak: 14d
1 send-back lesson promoted to PRINCIPLES.md (P-13 — tests own their
own filesystem) · 1 prompts revision pinned · 0 rollbacks

what the loop did this month
  • 47 tickets picked → 47 PRs merged (100% land rate)
  • 11 of 47 healed once; 2 healed twice; 0 escalated to human
  • top heal pattern: shellcheck SC2086 (×6) — see fleet prompts-suggest
  • top failure mode: test wrote to non-isolated path (×4) — see PRINCIPLES P-13
  • cheapest ticket: project-2/0043 ($0.07) · most expensive: project-1/0040 ($0.93)

kit @ 8a20547 · prompts pin ee94b3a · LESSONS 412 lines · CROSS_LESSONS 630 lines
generated by `fleet recap --public` · agent-fleet/agent-fleet
```

Subtraction: the operator stops composing the post. The command IS the
post.

Per P-5 (operator confidence over feature richness), the win is
converting "I should post about agent-fleet but I'd have to write a
paragraph and redact slug names and it's just too much friction" into
"I ran one command and screenshotted the result."

### Stakeholder
This is **moat-widening on the acquisition axis** — the kit's first
PUBLIC-FACING surface designed for outward distribution rather than
operator-private telemetry. Per the brief's "outward-facing
acquisition surfaces … a one-command narrative recap, an opt-in
social-share snippet" — this is the direct answer.

The `--public` flag is the load-bearing primitive: it converts every
identifying string in the output into a stable, anonymized token
(`project-1`, `project-2`, ...) using a slug → ordinal map computed
deterministically from the discovered slug list (sorted
lexicographically) so the same fleet produces the same `project-1`
across invocations. PR numbers are stripped entirely from the public
render (replaced with the count `47 PRs`); ticket ids are PRESERVED
because they're not identifying (every ticket file is public in the
agent-fleet repo) but slug-prefixed via `project-1/0043`. Dollar
amounts are PRESERVED (the cost story is the headline).

Per P-6 (telemetry is the source of truth), `recap` is a PURE
COMPOSER of existing reads — no new event types, no new state file.
It calls the same helpers `fleet weekly` (0025), `fleet streak`
(0042), `fleet ticket-cost` (0047), and `fleet prompts-suggest`
(0045) already use; the novelty is the narrative composition + the
anonymization filter.

Per P-1 (smallest viable change), the diff is the composer + the
anonymizer + the public-render filter. ~400 lines of new shell, no
runtime deps.

Compounds 0025 (`fleet weekly` — shares the 30-day rollup math),
0027 (`fleet badge` — shares the cost/PR-count fold), 0042 (`fleet
streak` — shares the streak compute), 0045 (`fleet prompts-suggest`
— surfaces the top promoted lesson), 0047 (`fleet ticket-cost` —
surfaces the cheapest/most-expensive ticket).

Per P-3 (heal in-flight before new work), `recap` is read-only and
cheap (~one events.jsonl + runs.jsonl read per slug) — never blocks
heal work.

### User (operator on a Friday afternoon, friend just asked
"what's agent-fleet?")
Operator runs `fleet recap --since 30d --public`. Sees the 12-line
block. Selects the terminal window, takes a screenshot, pastes it
into the Slack DM. Total time: 8 seconds. Friend reads the
screenshot, sees `5 projects, 47 PRs merged, $6.18 total spend`,
and asks the follow-up question that converts: "wait, $6.18 for
the WHOLE MONTH? what's the catch?" That follow-up question is the
acquisition moment.

Without this command, the same conversation goes: friend asks,
operator means to respond, opens terminal, runs `fleet weekly`,
remembers slug names are private, drafts a paragraph in their
head, gets distracted by something else, never replies. The
asymmetry between "8 seconds and one screenshot" and "5 minutes
of composition" is enormous; the kit captures the FORMER.

Per P-5, the win is converting the kit's most distinctive number
($6/month to ship 47 PRs) into a frictionless brag.

### Growth
This is the SINGLE most-leveraged growth ticket the backlog can
currently ship. Every prior growth surface (`kickstart --demo`,
`onboard`, `pr-footer`, `badge`) answers a question the operator
has already brought a hostile evaluator to: "let me prove it
works." `recap` answers the question the operator's NETWORK
has not yet brought to them: "what does this DO?"

The public mode also enables a future "ROI gallery" surface —
operators who run `fleet recap --public` can paste the output
into a shared GitHub Discussion / showcase page. v1 doesn't
build that surface; v1 builds the snapshot that makes it
possible.

Per the brief's "Outward-facing acquisition surfaces: the kit
has no good 'show me what this is doing for me' command that
an operator could screenshot and paste into a tweet/Show HN
post" — this is exactly that command. Differentiated from
`fleet badge` (0027) which is a single shields.io line: `recap`
is a narrative paragraph with verbs, counts, and a kit SHA.

The acquisition path now has seven moments:
`kickstart --demo` (see the loop), `preflight + onboarding-check`
(install it), `pr-footer` (0044, in-PR trust artifact),
`prompts-suggest` (0045, self-improvement signal), `vacation`
(0046, retention safety), `ticket-cost` (0047, cost
transparency), and now `recap` (network-facing brag).

## Acceptance criteria

Each box maps 1:1 to a test scenario in `tests/recap.sh`.

- [ ] `bin/fleet recap` is a new subcommand. With no flags walks every
      project discovered via `agents.config.sh` under the standard
      discovery roots (same set as `fleet overview`), reads each
      project's `runs.jsonl` + `events.jsonl` for the trailing 30
      days, and prints the 12-to-18-line narrative block from the
      User-lens example. Exit 0 always. Test asserts the render via
      fixture data files.
- [ ] `bin/fleet recap --since <Nd|YYYY-MM-DD>` overrides the
      default 30-day window. The default is 30d (matching
      `prompts-suggest` and `ticket-cost`). Test asserts each format.
- [ ] `bin/fleet recap --public` replaces every slug name with a
      stable ordinal token (`project-1`, `project-2`, ...) using a
      slug→ordinal map computed by sorting discovered slugs
      lexicographically. The mapping is stable across invocations
      (the same fleet always produces the same `project-1`). PR
      numbers are STRIPPED from the public render (replaced with
      "47 PRs"); ticket ids are PRESERVED, slug-prefixed via
      `project-1/0043`. Test asserts via a fixture fleet of 3
      slugs that the public output contains no slug name and no
      `pr=#N`-shaped substring.
- [ ] The render is bounded to between 12 and 18 lines (NOT
      counting the header) so the block screenshots cleanly on a
      laptop terminal. Empty sections fold rather than print a
      blank line. Test asserts via `awk 'END { print NR }'` on the
      rendered block.
- [ ] The "top heal pattern" line reads the trailing-window
      `infra_flake_rerun` events (ticket 0020) plus the heal
      pattern catalog from `lib/heal-catalog.sh`, picks the
      single highest-frequency pattern, and renders
      `top heal pattern: <name> (×<count>) — see fleet
      prompts-suggest`. When zero heal patterns recurred,
      prints `top heal pattern: none (clean window)`. Test
      asserts both branches.
- [ ] The "top failure mode" line reads the trailing-window
      `lesson_draft_emitted` events (ticket 0022), normalizes
      headlines via the same `prompts_suggest_normalize_headline`
      helper from ticket 0045, picks the single highest-frequency
      normalized headline, and renders `top failure mode: <text>

      <text> (×<count>) — promotion candidate` when no matching
      P-N is found. Test asserts both branches via fixtures.
- [ ] The "cheapest ticket / most expensive ticket" line reads
      every `runs.jsonl` row in the window across the fleet,
      attributes each row to a ticket via the same filter
      `fleet ticket-cost` (0047) uses, sums per ticket, and
      renders the min and max as `project-K/NNNN ($X.YY)`. When
      no tickets are attributable, prints `cheapest /
      most expensive: not attributable in window`. Test
      asserts.
- [ ] The header line is `<top-level-slug> · <Nd>-day recap ·
      <start-date> → <end-date>` in non-public mode, where
      `<top-level-slug>` is the kit's own slug

      `agent-fleet · <Nd>-day recap · <start-date> →
      <end-date>` (the kit name itself is open-source and

      `generated by \`fleet recap --public\` ·
      agent-fleet/agent-fleet`. Test asserts both modes.
- [ ] `bin/fleet recap --json` emits one JSON object
      summarizing the recap: `{"window": "<Nd>", "start":
      "<iso>", "end": "<iso>", "public": <bool>,
      "projects_count": <int>, "prs_merged": <int>,
      "total_spend_usd": <num>, "median_ticket_cost_usd":
      <num>, "current_longest_streak_days": <int>,

- [ ] `bin/fleet recap --help` prints USAGE mentioning

## Out of scope

The dev agent will NOT do these even if they seem related.

- POSTING the recap anywhere (Slack, Twitter, GitHub
  Discussion). v1 prints to stdout; the operator copies.
  Auto-posting violates the operator-confidence Hard NO.
- A `--markdown` mode that emits a code-block-formatted
  block ready to paste into a GitHub Discussion. The
  text render is already markdown-paste-clean
  (monospace-friendly). A future `--markdown` flag is
  v2 if operators ask.
- An image-generation mode (`--png`) that renders the
  recap as a real PNG for social cards. v1 is text
  only; image rendering would require a runtime dep
  (no shell-only path to a PNG) and violates the
  "shell-only" Hard NO.
- A CROSS-FLEET aggregation ("show me agent-fleet
  community stats across every public install"). v1
  is one operator's fleet. The community surface is a
  separate ticket.
- Auto-detecting which slugs are "private" vs
  "public" (some operators may want to disclose
  `agent-fleet` itself but not the others). v1 is
  binary: `--public` anonymizes all discovered slugs;
  `--public --keep-slug agent-fleet` is v2 if
  needed.
- A LIVE recap (auto-refreshing in a TTY). v1 is
  one-shot; live mode is `fleet tail` (0015)'s job.
- Including a CHART (ASCII sparkline of cost over
  time). v1 is text only; a sparkline is v2.
- A `--since 1d` minimum window check. The operator
  is the authority; a 1-day window is valid (the
  output may be very small but that's correct).
- An `--exclude <slug>` flag. v1 anonymizes all
  slugs in public mode and shows all slugs in
  private mode. Per-slug exclusion is a v2 ask.
- Integration with `fleet morning` (0036) or
  `fleet weekly` (0025) — those remain
  operator-private. `recap` is the public surface;
  the others are not.
- A launchd schedule. Operator-invoked only — a
  public artifact is an operator decision, not a
  background task.

- `bin/fleet` — eight helpers, ALL defined ABOVE the dispatcher
  block per LESSONS 2026-06-05 (forward-reference trap):
  - `recap_discover_slugs` — reuses `overview_discover_slugs`.
  - `recap_compute_anonymizer_map` — given a list of slugs, sorts
    them lexicographically and returns one TSV line per slug

    skips empty rows. Per LESSONS 2026-06-05 (bash 3.2 LC_ALL
    caching), the sort is `LC_ALL=C sort`.
  - `recap_collect_per_slug` — for one slug + window, returns a
    TSV summary (`slug<TAB>prs_merged<TAB>spend<TAB>heal_count
